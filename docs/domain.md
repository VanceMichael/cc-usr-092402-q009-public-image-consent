
# 领域约定

公众影像授权核对服务记录摄影作品声明、人物授权与公开用途中的本地业务事实。主体使用不含真实身份的引用编号，时间字段采用带偏移量的 ISO 8601 字符串，文件或正文只保存 `sha256` 摘要及本地引用。

`contracts/entities.json` 列出交换字段、枚举与端点，字段名称是稳定的接口约定。无效输入在 HTTP 边界返回结构化错误（400 `invalid_request` / 404 `not_found` / 409 `conflict`），不能通过修改样例数据绕过校验。SQLite 文件由 `DATABASE_PATH` 决定，开发环境默认写入 `data/app.sqlite3`。

## 核心对象与关联

原始作品（work）关联作者与作品摘要；拍摄场次（session）挂在作品下，携带拍摄时间与地域。人物识别声明（person_claim）把人物引用钉在某作品画面的归一化 bbox 上，角色区分主体、临时演员（extra）、观众等。监护关系（guardianship）记录未成年人与监护人在某时间段内的关系及证明摘要。授权（grant）不可变，按用途/渠道/地域数组（`*` 为通配）和起止时间表达；授权可限定到场次。撤回（grant_revocation）是独立登记的事实，不删除授权行。

## 版本可追溯链

每个作品先登记 `original` 版本，其在场人物直接来自识别声明。派生版本逐版继承并重新计算：

- `crop`：只保留与裁剪框相交的人物，bbox 坐标重映射到裁剪后画面；
- `mask`：遮蔽框覆盖人物框面积 ≥ 0.5 时该人物记为 `masked`，无法辨认即无需授权；
- `composite`：多个来源版本按 placement 贴片取并集，同一人只要在任一来源中未遮蔽就仍可辨认（遮蔽条件取 AND）；
- `subtitle`：字幕替换若具名提及某人，即使画面已遮蔽，文字仍使其可识别，授权要求恢复。

每次派生保存新版本摘要与派生 spec，可沿 `parent_version_id` 与 `version_sources` 回溯整条链。

## 门控：多人最严格条件

对「版本 × 用途 × 渠道 × 地域 × 时点」的判定按人物逐个进行：

1. 已遮蔽（obscured）人物不提出授权要求；
2. 成年人授权必须本人签署；未成年人必须由在判定时点监护关系有效的监护人签署；
3. 授权须在判定时点已生效、未到期、未撤回，且用途/渠道/地域均被覆盖；场次限定授权只对该作品所属场次生效；
4. 任一可辨认人物 blocked，整体即无效；有效期取全部在场人物授权的最早到期。

## 时点重放（迟到事实不倒改历史）

所有门控都支持 as-of 重算：只有 `recorded_at <= as_of` 的授权、监护关系与撤回事实参与判定；撤回在其登记之前不存在。因此事后补登记（哪怕回填 `valid_from` 或 `revoked_at`）不能改变发布时刻已固化的审批证据。发布时把当时完整证据（版本摘要、授权范围、遮蔽状态、逐人判定、批准链）连同其摘要写入 `publications.evidence`，此后不再被事实变化改写。

## 用途方案与无利益关系审核

策展人提交用途方案（proposal）；pending 期间可编辑，每次编辑生成 revision 留痕，已决方案不可改。批准（approval）必须由与提交人、作者、版本制作人、在场可辨认人物及授权签署人均不同的审核人作出；系统同时复核批准时点门控通过、方案期限不超过授权最早到期。拒绝不需要门控通过。

## 发布、撤回与处置清单

只有 approved 方案可发布，同一方案同时只允许一条 active 发布。撤回某授权时，仅冻结发布证据中实际依赖该授权且仍 active 的发布（其它渠道、其它发布不受影响），并为每个冻结发布按渠道生成处置事项：现场撤展、社媒下架帖文、巡展撤回物料；处置闭环需登记处理时间。

## 对外与对内视图

- `GET /verify` 是对外核验面，只回答该版本对指定用途/渠道/地域（可带 as_of）是否有效（布尔），不暴露人物与授权细节；
- `GET /admin/proposals/{id}/chain` 与 `GET /admin/publications/{id}/evidence` 是内部面，可重现任一发布时间采用的影像摘要、授权范围、遮蔽处理、修订记录与批准链，并校验证据摘要自洽。
