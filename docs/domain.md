
# 领域约定

公众影像授权核对服务把摄影作品声明、人物识别声明、监护关系、拍摄场次、授权用途、地域和期限关联为**可追溯版本**，回答“某个裁剪/打码/合成/字幕版本在指定用途、渠道、地域与时间点是否仍可公开”。主体使用不含真实身份的引用编号；时间字段采用带偏移量的 ISO 8601 字符串；文件或正文只保存 `sha256` 摘要及本地引用。

## 核心事实链

拍摄场次 `sessions` → 原始作品 `works` → 人物识别声明 `recognitions`（某人出现在某作品的归一化区域）→ 人物 `persons`（含未成年人与监护关系）与授权 `grants`（用途/地域/期限，未成年人由监护人授予）。

## 可追溯版本

`versions` 以血缘方式记录 `original/crop/mask/composite/subtitle`。派生版本时**继承并重新计算**每位人物的可见状态（`version_persons.state = visible|masked`）：

- `crop`：只保留与裁剪区域相交的可见人物，坐标重基到裁剪后画布。
- `mask`：命中的人物置为 `masked`，之后**不再需要其授权**。
- `composite`：合并多个来源，任一来源可见即视为可见（取更严）。
- `subtitle`：字幕替换不改变可识别性，原样继承并重算固化。

## 时点核验与最严格合并

`evaluate(version, purpose, channel, territory, at)` 对该版本中每位 `visible` 人物，在 `at` 时点寻找已登记、已生效、未到期、未撤回、且覆盖用途与地域的授权；未成年人还要求授权人是其监护人。多人影像**合并最严格条件**：任一需要授权的人不满足，则整版对该用途无效。已遮蔽人物不参与。

- 授权以 `grants.created_at` 为登记时点，缺省为服务器当前时间；`at` 之后才登记的授权不参与——**迟到授权不能倒改已发布的审批证据**。
- 撤回 `withdrawals` 以 `withdrawn_at` 生效。

## 审批与发布证据

编辑提交用途方案 `plans`（携带利益相关方），只能由**非提交人且非利益相关方**的审核人裁决 `approvals`；批准时再做一次时点核验，未通过不得批准。发布 `publications` 写入即**不可变**，固化：影像摘要、可见/遮蔽人物、采用的授权范围、用途/渠道/地域、发布时间与完整批准链。

## 撤回处置

撤回不删除、不改写任何历史证据，而是：

1. 只冻结**实际承载该可识别人物**的发布渠道（`channel_freezes`）；
2. 为受影响的在途发布生成 `disposition_items` 处置清单（takedown）；
3. 使撤回之后的新发布在发布时点核验失败。

人物已被遮蔽的版本/渠道不受影响。

## 对外与对内视角

- 对外 `POST /v1/verify` 只返回该版本对指定用途 `{valid: bool}`，不暴露人物或授权细节。
- 内部 `POST /v1/internal/evaluate` 返回逐人裁决与失败原因；`GET /v1/internal/publications/<ref>` 能以发布时间为“现在”**重放**，重现任一发布时间采用的影像摘要、授权范围、遮蔽处理和批准链，并与不可变证据比对一致性。

无效输入在 HTTP 边界返回结构化错误（`error.code/message/details`）。SQLite 文件由 `DATABASE_PATH` 决定，开发环境默认 `data/app.sqlite3`，迁移按文件名顺序应用。
